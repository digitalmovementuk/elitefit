# Reviews lane report: section #reviews

Version: v3.0 — 2026-10-02 · lane: reviews (Sonnet 5.5) · marker `_build/ready/reviews.ready` · live: http://127.0.0.1:8201/#reviews

## 1. What is built

A section after Pricing: head (eyebrow, h2, one-line lead), a raised readout card with the Google rating and the review count as the large mono numerals, five verbatim Google quotes as a stacked hairline list, and one plain link to the club's Google listing. No embed, no third-party script, no request to any other origin.

| Part | How |
|---|---|
| Rating | `4.7` in Fragment Mono, 96 to 120 px on a phone, `--fs-giant` (135 px at 1440) from 760 px; tracking -0.14 em so the point does not float between the digits; "out of 5" beside it; five monochrome stars filled to the rating (four full, the fifth 70 %). `data-count` carries the value, the text IS the value, so the motion layer rolls it |
| Count | `488` in the same face (56 to 80 px), label "Reviews", `data-count` likewise. Both numerals come from `reviews.json`; if a number is missing its row is hidden, no placeholder stays |
| Quotes | five items, 20 px on a phone (never below 16), 22 to 30 px from 760 px; curly quotation marks drawn by CSS and hung, so every line shares one edge; the member's name as published (not upper-cased), five small stars with an aria-label ("5 out of 5 stars"), a plain "Google review" label |
| Link | "Read all reviews on Google" with an arrow, ghost button, 52 px high, full width on a phone; `target="_blank" rel="noopener"` plus a visually hidden "(opens in a new tab)"; the href is the maps URL from `reviews.json` (the partial carries the same URL as a no-script fallback) |
| Layout | one column on every phone width (readout, quotes, link); from 760 px the readout sits left and stays pinned (sticky, below the header) while the quotes pass on the right, the link under the last quote |
| Keyboard | the only tab stop is the Google link (focus ring from base.css, 2 px, `:focus-visible` confirmed in Chromium); WebKit in Playwright does not tab to links by default, so the tab test ran in Chromium only |
| Reduced motion, data-saver | the section has no motion of its own; the skeleton pulse is stilled by base.css; the motion layer is off, numerals and quotes show at once (measured in WebKit with reduced motion on) |
| No script | heading, lead and the Google link stay; readout and list are hidden (`html:not(.js)`), nothing half-empty |

Files: `partials/45-reviews.html`, `assets/css/reviews.css` (2.6 KB gz with comments, 1.7 stripped, budget 3), `assets/js/reviews.js` (2.1 KB gz, 1.5 stripped, budget 4), `assets/data/reviews.verified.json` (new, 1.0 KB gz), `copy/slots/reviews.json` (11 slots), `_build/requests/reviews-json-trimmed-quotes.md`.

## 2. Which quotes, and why only those

Rule in `reviews.js`: a quote shows only if `stars === 5`, it is not flagged `verified: false`, `origin === 'google'`, and, where `reviews.json` holds the same author, that file's text (minus a trailing ellipsis) is the start of ours. This is the hero's rule (5 stars, not unverified) plus the FACTS list. The data file holds only quotes FACTS section 14 marks ELIGIBLE, generated byte for byte from `_build/facts/reviews-verification.json` (curly apostrophes, the club's own spelling, the space before the exclamation mark in the last one; the decorative emoji the club appends is left out).

Why the placeholders are built from the quotes' shapes: the five list items exist in the HTML before the data arrives (JS fills them in place, so a reveal hook on the list keeps working). A min-height guess shifts everything below when the real text lands. Each placeholder is a stand-in for its quote: every letter and digit swapped for a different one of the nearest width in the same typeface (so nothing readable), spaces and punctuation kept, transparent, `aria-hidden`, drawn as grey bars, gone as soon as the data is in. It wraps like the real text: same line count at 153 of 155 quote-widths over 31 widths from 320 to 1920 px, and none of the misses is at a common phone width. They are not copy and carry no information.

## 4. Copy slots and facts

`copy/slots/reviews.json`: `reviews.eyebrow`, `.title`, `.lead`, `.score_k`, `.score_of`, `.count_k`, `.link`, `.link_new`, `.list_aria`, plus two lexicon strings JS composes (`.stars_aria` with `{n}`, `.src_google`). Each has role, max, provisional text and a note. Not slots because they are data: the rating, the count, every quote and its author. `data-fact`: F-REV-01 (rating row), F-REV-02 (count row), F-REV-03 (eyebrow, lead, link), and one F-REV id per quote item (set from the data file when rendered). `copy/copy-facts.json` (copy review lane's file) was not touched: it still needs the 11 `reviews.*` rows.

Provisional wording, for the copy pass to judge: title "What people say about the club" (says "people", not "members": two of the five are guests); lead "A few of the reviews from our Google page, word for word." (discloses the selection, says unedited, no number, no "verified"); eyebrow "Google reviews".
