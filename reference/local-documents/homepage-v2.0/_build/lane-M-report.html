3. What I verified, and how

Server: python3 -m http.server 8802 --directory OUT. Preview: _build/preview/M.html (all 12 real partials, no stubs needed, all lane CSS, api/shop/schedule/hero/motion JS, M-stub-main.js).

Measured: - Every state in motion-states.json (84 runs: WebKit 390×844 touch DPR 2, Chromium 1440×900) executed by M-states.mjs: all asserts pass, console clean in every run (only the mock adapter's info line), layout shift without recent input 0.0000 in every run. Filmstrips cut from the context videos: M-state-<id>-<profile>-r3.png. - Frame time (Chromium, CDP CPU 4x, real scroll gestures, 3 runs each; table in MOTION-AND-DESIGN §9): p95 16.7–16.8 ms in every scenario (hero, Recharge, long scroll, price morph, lift, checkout; phone and desktop). Dropped frames (> 20 ms): 0 % in the Recharge and long-scroll runs on both profiles; ≤ 0.5 % (one frame) in price morph, lift and checkout desktop; one of three phone hero-load runs had an extra 78 ms load-time long task. - No horizontal scroll: scrollWidth <= innerWidth at all 14 CONTRACT §8 widths (320 → 1920) in WebKit and Chromium, after a full scroll (all reveals done) and again with the checkout open on the widest price (52 weeks, Elite). - CLS: 0.00 (no-input) everywhere. Input-driven shifts exist only in the checkout (sheet height between steps, summary price width): identical with motion off, so they belong to L2's layout (see §5). - LCP: one entry at first paint (phone 120–172 ms, desktop 124–136 ms at CPU 4x, no network throttle); headline at opacity 1 on the first probed frame. - Start-up: motion.js adds no long task on the phone profile and none beyond the 54 ms baseline on desktop (measured with motion.js blocked as control). - Weight: motion.js 14.0 KB gzip as authored (10.6 KB without comments), motion.css 8.0 KB gzip (3.2 KB without comments). Together with the other lanes' JS (api 8.5, shop 11.7, schedule 5.6, hero 3.6 KB gzip) the page ships about 43 KB gzip of JS as authored, above stack-shop §8's 30 KB guidance (not a CONTRACT §8 budget); stripping comments in build.mjs is the cheap fix. - Reduced motion, data-saver, no JS: states fallback-* pass (no motion-ok, motion-live present, reel off, layout complete).

Fixed because the measurement or the close-ups showed it (first build → now): 1. Odometer cells collapsed where a host sets line-height: 0 (hero.css on the clock): the overlay now has its own line metrics and a zero-height margin box. 2. Tab pill jumped instead of sliding (double placement), and a delayed colour flip left labels invisible on long moves: rebuilt as a clip window over light label copies (no text is ever ink on ink). 3. Picture reveal snapped (clip-path: none does not interpolate) — then replaced entirely: the clip-path reveal dropped 3–4 % of desktop frames, so it is now a transform-only cover. 4. Recharge dot indicator (clip layer inside a sticky row) repainted on every scroll frame: now a transform-only dot. Recharge desktop dropped frames 7.3 % → 0 %. 5. Recharge desktop dissolve superimposed the two rooms' words: outgoing words and number leave first (360 ms), new number from 280 ms, new words from 480 ms. 6. Hiding the <video> until it played produced a late second LCP entry: now the poster <img> on top fades out instead. 7. Priming read layout at start-up (+22–55 ms long task at 4x): now an observer classifies, work runs in idle chunks. 8. The hydration render of the schedule animated in the first screen: entrance now only after a tap on a day chip.

Judged by eye only: the look of every state in WebKit and Chromium from the filmstrips (Playwright cannot throttle WebKit's CPU, so WebKit frame timing is not measured); the odometer, clock, counter, Recharge rolls and pill close-ups (M-odo-*-r2.png); the emotional read of the zones' pacing.
